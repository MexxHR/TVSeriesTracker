## Original failure and root cause

User-supplied GitHub annotation: Startup failure; no job started and no provider/runtime coverage result exists. Invalid workflow `.github/workflows/provider-coverage-audit.yml`, line15 column13 and line16 column12: unrecognized named-value `runner`, expression `runner.temp`.

The original TEMP and TMP values referenced runner.temp in **jobs.audit.env**. GitHub evaluates that key without the runner context; valid YAML does not imply valid Actions expressions. The earlier YAML-only check missed this context restriction. The new regression check reconstructs both invalid job-env lines and rejects them before a GitHub run.

GitHub's [context availability table](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts) excludes runner from jobs.<job_id>.env and allows it in step-level with inputs. The annotation is explained and statically reproduced from the source; no new GitHub execution is claimed.

## Implemented fix

Removed TEMP/TMP from job-level env. The first execution step, **Initialize runner temporary paths**, creates `$RUNNER_TEMP/coverage-tmp` and appends TEMP/TMP values to `$GITHUB_ENV` with printf. Subsequent steps receive those values. These are runner shell environment variables used after runner assignment, rather than expressions evaluated in job env. No filesystem path is hardcoded.

The temporary registry/output locations remain outside the repository checkout. Audit producer, snapshot, summary and artifact upload paths retain their existing meaning. Provider Coverage Audit methodology and runtime implementation are unchanged.
