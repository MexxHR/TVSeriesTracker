# Official Data automation (V2.3.5)

V2.3.5 treats exhausted HTTP, network and access blocks as `PROVIDER_UNAVAILABLE` warnings. The unavailable series keeps its exact verified record, including `lastChecked`; without an existing record, none is invented. Valid changes from other series remain publishable after validation of the complete candidate dataset. `SERIES_VALIDATION_FAILURE`, including conflicting strong dates and malformed evidence, blocks the whole run by default. `GLOBAL_SAFETY_FAILURE`, including bad schema, corrupt audit, mass changes and write verification, also blocks it. Unexpected programming exceptions propagate and block publishing. This conservative series rule avoids publishing while evidence is contradictory.

Dry-run and production use the same `publishable` decision. Dry-run never writes JSON or audit. Production stages and validates complete JSON and audit, atomically replaces each file, verifies the result, and restores originals on write or verification failure. Audit entries describe only published factual changes. An outage alone causes no write, no `generatedAt` change and a successful workflow with a visible warning. Factual changes advance dataset `generatedAt`, while an unavailable series's `lastChecked` stays intact. The workflow commits only after updater success. **The first GitHub Actions V2.3.5 run must use `dry_run=true`; keep `OFFICIAL_DATA_LIVE_ENABLED` unset until the report is reviewed.**

V2.3.4 separates lifecycle assertions and explicit premiere dates into independent facts. When one sentence renews MobLand Season Three while mentioning the Season Two premiere, the date belongs only to Season Two. An ambiguous date without a nearby explicit season is discarded; the verified renewal remains usable. The strict validator still rejects malformed date facts, and conflicting verified dates still fail the series.

V2.3.3 also requires whole-word season numbers: a publication year such as 2026 cannot become Season 26. The Lioness Season Three announcement and its separate premiere article are merged without changing the lifecycle source.

V2.3.2 discards incomplete response bodies and retries expected transport failures, HTTP 429 and HTTP 5xx at most three times per URL. Backoff is 1 then 3 seconds. HTTP 403/404 and responses over 8 MB fail immediately. Exhausted failures become endpoint errors, so configured fallback URLs and other series continue. Retry logs include the URL, attempt and failure type, never the HTML body.

`.github/workflows/update-official-data.yml` runs daily at 07:17 UTC and via `workflow_dispatch`. Manual runs default to `dry_run=true`. **After deploying V2.3.5, the first GitHub Actions run must be a dry-run.** Scheduled runs also stay in dry-run mode until the repository Actions variable `OFFICIAL_DATA_LIVE_ENABLED` is set to `true` after reviewing that first report. This is a one-time activation; subsequent daily runs need no approval. It uses Python 3.12 standard library and the repository `GITHUB_TOKEN` (`contents: write`); no paid service, LLM, PAT or server is required. The Android app continues to consume the same schemaVersion 1 JSON from raw GitHub. Startup refresh (stale after 24 hours), Settings refresh and Room cache already exist.

Run locally from the repository root:

```bash
python -m unittest discover -s official-data/automation -p 'test_*.py' -v
python official-data/automation/update.py --dry-run
```

`sources.json` registers the 12 fixed initial titles by existing `tmdbId`, title, provider, official URL, allowed domains and aliases. Optional `evidenceUrls` add exact original-provider articles; optional `fallbackUrls` supply alternative original-provider endpoints when the primary fails. The Madison has an explicit [Paramount+ Season 3 announcement](https://www.paramountplus.com/sneak-peak/the-madison-renewed-season-3/) as evidence. WBD has direct US and Canada press releases as fallbacks to the property listing. The extra `paramountplus.com` allowlist entry applies only to The Madison; WBD remains restricted to `press.wbd.com`. Provider adapters are Paramount Press Express/Paramount+, Netflix Tudum, Apple TV Press, WBD Pressroom and Amazon About Amazon. Each adapter selects a bounded set of candidate official release links. Existing canonical source URLs are also checked. The updater fetches at most ten article candidates per title plus the listing/fallback probes, with a 12-second timeout, 8 MB response limit, identifying User-Agent, and two backoff retries only on transient HTTP/network errors. Every request, redirect and accepted evidence URL must remain HTTPS and within the title's allowlist. No search result or third-party page becomes evidence.

Detection requires the series name and season in the same title/sentence as an explicit renewal, final-season, cancellation or premiere statement. A date needs a premiere verb and a valid month/day/year; when an official release omits the year, the announcement year is used only if unambiguous. A year-only premiere keeps `releaseDate=null`. Cancellation requires an explicit cancellation/no-return statement. Absence of news never means cancellation. False negatives are preferable to speculative facts.

All fetching/detection finishes before validation/writing. The validator checks registry identity, schema, dates, status, HTTPS/domain, duplicate IDs, nonempty source, generatedAt and season monotonicity, preserved old records, and a maximum of **four factual series changes per run**. An unavailable provider preserves its record and appears as a warning. Malformed evidence and parser failures block the run as series validation failures. Independently verified changes from healthy providers may be written and committed when the full candidate is safe. Global validation failure, including the mass-change guard, prevents every write. A provider block is a known V2.3 limitation for that provider, not a reason to trust another source for its title.

Conflict rules: gather and validate all selected facts before choosing the highest verified season, regardless of article order. For one season, final/canceled status outranks renewal; an independent verified premiere date does not replace RENEWED or FINAL_SEASON. Date-only evidence uses RELEASE_DATE_CONFIRMED when there is no lifecycle evidence. CANCELED receives no date. Distinct explicit dates from current facts or existing verified data fail the provider unless a newer official statement explicitly says the premiere was moved/rescheduled; chronological order alone never resolves conflict. The canonical sourceUrl proves lifecycle status, while a separate premiere URL appears in supportingSourceUrls in the audit. Existing records remain untouched on no evidence, HTTP error or parser error. generatedAt and audit history advance only for factual changes. No HTML is logged.

For monitored promotion, both monitored fact construction and independent replay rank the same validated evidence by the existing season/status/date priority. When those fields tie, official source URL, source name and remaining fact fields provide a stable descending lexical tie break. This avoids discovery and persisted-array order changing the canonical source. Equivalent duplicate facts do not change the chosen source; conflicting facts still fail validation. The trusted daily updater retains its existing source-selection behavior.

To add a series later, first determine the correct TMDB TV ID and official source, add a registry entry and provider link-selection rule if needed, add fixtures, and validate the canonical data. V2.3 intentionally does not generate registry entries for arbitrary TMDB additions. The bundled Android asset remains the release-time offline fallback; automated remote updates do not rewrite the asset or APK.

Provider HTML and geographic access can change. The real V2.3.2 GitHub Actions dry-run successfully fetched Paramount, Netflix, Apple and Amazon, but all three configured press.wbd.com URLs returned HTTP 403. Local checks also returned 403 for the pressroom listing, article, attempted RSS and JSON formats. The public WBD corporate newsroom is reachable but lists corporate news and links to press.wbd.com for the Press Room; its feed URL returned 404. The official HBO Max show page is reachable but currently has Season 3 content and no Season 4 release evidence. No tested alternative provides a trustworthy, current show-level official WBD feed or article body. Therefore the WBD allowlist and fallback behavior remain unchanged: provider failure is reported and the verified The White Lotus record is preserved. Do not treat search results or a third-party mirror as authority. A real GitHub Actions dry_run=true remains required after V2.3.5 deployment; OFFICIAL_DATA_LIVE_ENABLED remains off.
