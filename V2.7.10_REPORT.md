## Activation, routing and source policy

`official-data/discovery_providers.json` adds only HBO, with `productionActivated=true`, routingNames `[HBO]`, exact regional host for both candidate/evidence domains, HTTPS root/sitemap/post entry points, es/ES and wildcardTrust=false. `update.ADAPTERS` adds HBO; MAX/FX are absent. No live source registry entry is inserted.

Production routing requires the sole supported network identity HBO (existing case/whitespace normalization). HBO plus Max/HBO Max or another network fails closed. Max/HBO Max networks are rejected before the legacy WBD routing branch, so they cannot enter HBO or acquire production activation through that branch. Other standalone provider routes retain their behavior. Ownership, studio, distributor, company metadata, homepage, source host and article brand cannot route a series into HBO. Disabling the HBO config prevents both discovery and persisted HBO promotion validation.

Provider identity and publisher provenance remain separate. The publisher/sourceName is **Max Press Spain**, never renamed HBO Press. A concrete article must pass the qualified requested/final/canonical URL and title checks and identify the requested title as HBO, not a Max original. Index/sitemap/search are discovery surfaces only. No wildcard regional trust or third-party authority was added.

## Qualified discovery and HTTP integration

New `hbo_production.py` wires the existing qualified helpers into production; it does not run the qualification runner or read corpus/oracle files. The actual V2.7.9 runner artifact is not a production runtime dependency and is excluded from the ZIP. Bounded runner excerpts in a separate test fixture support regression tests only.

Production uses the unchanged `hbo_max_discovery.py` pipeline: regional root, HTML/XML sitemap, post listing, actually observed pagination and public GET search template; canonicalization/deduplication, exact title relevance and deterministic generic ranking. Known/oracle article URLs are never runtime inputs or fallbacks. Missing discovery gives no verified facts. HTTP access uses the qualified strict decoder, bounded transport and exact redirect boundary. WBD 403 remains safe failure; no retry/bypass, proxy, cookie/session workaround or alternate client was added.

The unchanged crawler limits remain 24 index pages, 24 bounded title search pages, depth four, 4,000 extracted links per page, 4,000 article candidates and eight selected candidates per requested title. HBO discovery additionally caps HTTP calls at 120; at most eight monitored refetches follow the bounded selection (the crawler/candidate limits keep a normal single-title path within the qualified total bound). No unlimited crawl or external search fallback exists.

For the regional source's localized title identity, strict HBO metadata loading may additionally request TMDB es-ES details using the existing server-side token. Only a matching TMDB ID and nonempty name contribute an alias; no lifecycle/season/date/status is imported. Missing or invalid localized identity leaves a safe false negative. This avoids hardcoded production mappings for IT/The Gilded Age and does not translate titles heuristically.
