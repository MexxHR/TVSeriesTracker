# V2.7.8.1 — HBO/MAX Qualification Runner-State Hotfix

## Original failure and reproduction

The user-reported GitHub workflow failed in `test_schema_no_writes_and_local_inconclusive`, before `Real runner qualification`. The assertion compared `RUNNER_ACCESS_NEEDS_WORK` with expected `LOCAL_NETWORK_INCONCLUSIVE`. The subsequent missing-artifact error was secondary: no real qualification JSON had been generated.

Reproduced the original assertion before editing by running that single test with `GITHUB_ACTIONS=true`, using offline synthetic fetches. The exact state mismatch occurred. An initial local test attempt was blocked by sandbox permissions on the default temporary directory; the reproduction succeeded using the project's existing `.validation-temp` directory. No provider request was needed.

Root cause: the synthetic `run_q` helper called the real `q.run` without isolating execution context. `q.run` calls `http._is_github_actions(None)`, which reads `GITHUB_ACTIONS`. With synthetic network failure and the runner flag inherited from the host, the implementation correctly selected `RUNNER_ACCESS_NEEDS_WORK`. The test incorrectly assumed a local context.

This assertion from a synthetic unit test is not a provider qualification result from the failed GitHub workflow. The actual qualification step had not run. Both states are legitimate when used in their appropriate execution context.

## Minimal correction

The test-only `run_q` helper now accepts keyword-only `github_actions=False` and temporarily patches just `GITHUB_ACTIONS` to the explicit selected value around the synthetic call. The real environment detector remains active. The patch is restored after the call, including exceptions.

The LOCAL test executes under both simulated physical host values (`true` and `false`), proves the synthetic scope is `LOCAL_DIAGNOSTIC_ONLY`, both route states are `LOCAL_NETWORK_INCONCLUSIVE`, and the outer host value is restored. The new runner-context test selects `github_actions=True` while the outer host is false, proves `RUNNER_CONFIRMATION`, both route states `RUNNER_ACCESS_NEEDS_WORK`, no activation and protected-file integrity.

A second new regression test exercises the existing CLI artifact writer with a synthetic nonqualified result in an isolated temporary project. It verifies that normal completion writes the complete actual result object even when both providers need access work. It creates no placeholder artifact in the repository and does not perform live qualification.

No implementation module was changed: `hbo_max_qualification.py`, Spanish parser, discovery, source trust, WBD behavior, routing, seven-field independent reconstruction, negative/ambiguity requirements, ES date policy and the minimum of three distinct series per route remain byte-identical to V2.7.8.

## Workflow behavior

1. Checkout/setup.
2. Protected-file snapshot.
3. Safety/unit tests.
4. Real runner qualification.
5. Protected hashes and clean-checkout verification.
6. Explicit artifact existence check, then conditional artifact upload.

Only the test helper mocks context. The real qualification step uses the actual GitHub runner environment and existing TMDB secret mechanism. No runner/local override is added to that step.

The new always-run artifact check requires a nonempty dedicated JSON file. If present, it enables upload of `hbo-max-provider-qualification`. If absent, it emits `Qualification artifact was not generated; inspect preceding safety tests and real qualification step for infrastructure failure.` and fails; the upload action is skipped. Earlier failures remain failed. No empty/fake qualification JSON is generated. A normal nonqualified result is still uploaded. Existing permissions, manual trigger and production safeguards remain unchanged.

Static workflow assertions cover step order, conditional upload, explicit error, read-only permissions and absence of a real-step environment override. This local work does not claim that GitHub qualification has run successfully.
