## Root cause and contract correction

Previously build_report inferred runner execution solely from GITHUB_ACTIONS=true. The offline test supplies no token or fresh measured metadata. Inside Actions, that combination selected finalCoverageStatus=INCONCLUSIVE and RUNNER_INCONCLUSIVE instead of the local contract. With a token and metadata, the same environment-only inference could falsely grant authority to an ordinary library/test call.

The fix is general execution-mode separation, with no test-name or test-environment special case:

- `build_report(..., execution_mode="local")` and CLI default local. Merely running inside GitHub Actions cannot change that default.
- Actual audit step explicitly adds `--execution-mode runner-confirmation`.
- Runner confirmation requires that explicit mode, GITHUB_ACTIONS=true, the existing valid quality gate, a token and existing fresh-metadata measurement evidence. The existing measurement/quality requirements were preserved rather than relaxed.
- Explicit runner mode outside Actions is rejected before any source probe.
- No authority yet: finalCoverageStatus=AWAITING_GITHUB_RUNNER_CONFIRMATION. Local resultScope=LOCAL_DIAGNOSTIC_ONLY, including local/unit execution inside Actions. Requested runner execution without confirmation uses RUNNER_INCONCLUSIVE and remains pending.
- Confirmed execution: resultScope=RUNNER_CONFIRMATION and the existing finalCoverageStatus=GITHUB_RUNNER_CONFIRMATION.
- Existing safety failure semantics remain AUDIT_INVALID. Invalid output or final workflow safety gates revoke runnerAuthorityConfirmed and cannot leave RUNNER_CONFIRMATION on an invalid report.

`diagnosticStatus` is separate: INCONCLUSIVE when token/fresh-metadata measurement is absent; MEASURED when diagnostic measurement exists. MEASURED is not a provider success or authority claim. Existing per-case network/provider diagnostic findings, HTTP/source classifications and metrics remain untouched. JSON includes executionMode and runnerAuthorityConfirmed; Markdown displays diagnostic status, mode and scope separately. The audit methodology identifier auditVersion=2.7.14 remains unchanged; project release metadata is2.7.14.2.
